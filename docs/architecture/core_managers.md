# Глобальные менеджеры (Core Systems)

В игре «Стар80рс» управление состоянием, графическим интерфейсом и звуковым сопровождением централизовано. Для этого используется классический архитектурный шаблон **Singleton (Одиночка)**. Это позволяет осуществлять быстрый доступ к глобальным системам из любой точки кода (например, вызов проигрывания звука смерти штурмовика или обновление количества сердец на экране).

---

## 1. Концепция и Смысл глобальных систем

Связующие компоненты игры не зависят от конкретного сгенерированного уровня. При перегенерации комнат, стен и врагов, менеджеры ядра (`GameManager`, `UIManager`, `AudioManager`, `MenuController`) остаются нетронутыми в памяти. Это гарантирует непрерывность игрового процесса, стабильность UI-переходов и воспроизведения звуков.

*   **GameManager:** «Мозг» игры. Хранит глобальный прогресс (текущий уровень, ключи, кристаллы) и координирует правила победы и поражения.
*   **UIManager:** «Мост» между логикой GameManager/JediController и визуальными элементами HUD на экране (сердца, кристаллы ульты, индикаторы ключей).
*   **AudioManager:** Централизованный микшер эффектов, предотвращающий забивание памяти дублирующимися компонентами `AudioSource`.
*   **MenuController:** Координатор видимости экранов (панелей) интерфейса, управляющий фокусом внимания игрока.

---

## 2. Связующее визуальное и звуковое оформление

Менеджеры ядра напрямую не рендерят графику, но они хранят ссылки на спрайты UI и аудиофайлы:
*   **Спрайты сердец:** `heart.png` (полное сердце) и `empty_heart.png` (пустое).
*   **Спрайты кристаллов ульты:** `кристалл.png` и `пустой кристалл.png`.
*   **Звуковые ресурсы:** Проигрывание файлов `click.mp3`, `win.mp3`, `game_over.mp3`, `power-crystal-taken.mp3` и других централизовано через `AudioManager`.

## 3. Техническая реализация (Код)

Все менеджеры используют стандартную инициализацию Singleton в методе `Awake()`. Ниже приведен детальный разбор каждого класса.

### 3.1. GameManager (`GameManager.cs`)
Менеджер наследуется от `MonoBehaviour` и хранит ключевые параметры сессии.

*   **Ключевые свойства:**
    *   `public static GameManager Instance` — глобальная ссылка на синглтон.
    *   `public int currentLevel` — текущий уровень (от 1 до 15).
    *   `public int playerHealth` — базовое здоровье (всегда сбрасывается до 3 при старте уровня).
    *   `public int crystals` — количество собранных кристаллов для ульты (максимум 3).
    *   `public GridLevelGenerator generator` — ссылка на генератор сетки уровня.
    *   Пасхалки: `hasCopperKey`, `hasJadeKey`, `hasCrystalKey` — булевы флаги собранных ключей Холлидея.

*   **Важные методы:**
    *   `CollectKey(int keyIndex, string keyName)` — активирует флаг владения ключом, обновляет UI и проигрывает победный звук.
    *   `CheckEnemyCount()` — вызывается при смерти любого штурмовика. Если это уровень 10+ и остался последний враг, выдает Медный ключ.
    *   `StartLevel()` — сбрасывает здоровье игрока до 3, очищает сцену, вызывает генерацию карты и обновляет интерфейс.
    *   `LevelCompleted()` — останавливает время (`Time.timeScale = 0`), проверяет условия победы на 15-м уровне (`IsTrueVictory()`) и открывает соответствующее меню.
    *   `GameOver(string reason)` — запускает корутину задержки смерти и выводит панель GameOver.
    *   `SaveMyRecord()` — сохраняет максимальный пройденный уровень в реестр через `PlayerPrefs.SetInt("Record", currentLevel)`.

### 3.2. UIManager (`UIManager.cs`)
Отвечает за отрисовку HUD и обновление текстовых полей TextMeshPro.

*   **Компоненты и ссылки:**
    *   `public TextMeshProUGUI levelText` — индикатор текущего уровня.
    *   `public Image[] hearts` — массив изображений сердец на HUD.
    *   `public Image[] crystalIcons` — индикаторы ультимативной Силы (3 деления).
    *   `copperKeyUI`, `jadeKeyUI`, `crystalKeyUI` — иконки ключей.

*   **Методы обновления:**
    *   `UpdateHearts(int currentHealth)` — заполняет массив `hearts` спрайтами `fullHeart` или `emptyHeart`.
    *   `UpdateCrystals(int currentCrystals)` — заполняет индикаторы ульты в зависимости от переданного количества.
    *   `UpdateKeys(bool hasCopper, bool hasJade, bool hasCrystal)` — регулирует прозрачность (альфа-канал) иконок ключей на экране: если ключ собран, прозрачность `1f`, если нет — `0.2f` (затемнение).

### 3.3. AudioManager (`AudioManager.cs`)
Обеспечивает воспроизведение звуковых эффектов без прерывания при смене сцен или перезапусках уровней.

*   **Особенности:**
    *   Использует метод `DontDestroyOnLoad(gameObject)`, благодаря чему объект аудио-менеджера не уничтожается при перезагрузке сцены.
    *   Содержит единственный `AudioSource sfxSource` для проигрывания непотоковых звуков.
*   **Метод проигрывания:**
    ```csharp
    public void PlaySFX(AudioClip clip)
    {
        if (clip != null)
        {
            sfxSource.PlayOneShot(clip);
        }
    }
    ```
    Использование `PlayOneShot` позволяет воспроизводить несколько звуков одновременно на одном компоненте без их взаимного прерывания (например, одновременный выстрел штурмовика и взмах меча).

### 3.4. MenuController (`MenuController.cs`)
Координирует видимость панелей интерфейса на холсте (Canvas).

*   **Управляемые панели (GameObject):**
    *   `mainMenuPanel` — главное меню игры.
    *   `transitionPanel` — панель перехода между уровнями с шутками и подсказками.
    *   `victoryPanel` — финальная панель победы (обычной или истинной).
    *   `gameOverPanel` — панель смерти игрока с указанием причины.
    *   `introPanel` — панель со вступающим текстом (Intro Crawl).

*   **Методы переключения:**
    *   `HideAll()` — выключает абсолютно все панели перед стартом геймплея.
    *   `ShowGameOver(string reason, int level)` — включает панель смерти и передает в нее данные для печати текста.
    *   `ToggleJokes(bool isOn)` — булев флаг, позволяющий игроку включать/выключать шутки на экране загрузки.

## ⚠️ Важное архитектурное замечание для разработчиков

**Проблема дублирования данных здоровья:**
В текущей реализации здоровье игрока хранится в двух разных местах:
1.  Поле `playerHealth` в `GameManager.cs`.
2.  Поле `health` в индивидуальном контроллере игрока `JediController.cs`.

При получении урона изменяется только значение внутри `JediController`. Значение в `GameManager` остается неизменным на протяжении всего уровня и сбрасывается в `StartLevel()`.

При расширении игры (например, добавлении сохранения здоровья между уровнями или лечащих предметов) **рекомендуется избавиться от дублирования**: хранить здоровье исключительно в `JediController` и предоставлять к нему `public` доступ, либо полностью делегировать расчет урона синглтону `GameManager` для исключения рассинхронизации.
